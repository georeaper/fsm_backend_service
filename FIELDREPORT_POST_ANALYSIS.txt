ΕΛΕΓΧΟΣ POST /fieldreports
==========================

Το POST /fieldreports περιμένει το FieldReportCreateDto και αποθηκεύει μαζί
equipment, checkforms, inventories και special tools.

ΠΡΟΒΛΗΜΑΤΑ ΣΤΟ PAYLOAD ΤΟΥ FRONTEND
-----------------------------------

1. Τα παρακάτω πεδία δεν ανήκουν στο create DTO:

   - ContractName
   - TicketNumber

   Πρέπει να αφαιρεθούν από το POST request. Είναι πεδία παρουσίασης που
   επιστρέφονται από το backend και όχι πεδία που χρειάζεται να αποθηκεύσει.

2. Το StartDate έχει λανθασμένο έτος:

   "StartDate": "0026-01-21"

   Πρέπει να γίνει:

   "StartDate": "2026-01-21"

   Το backend σήμερα αποθηκεύει τις ημερομηνίες ως απλά String και δεν
   επικυρώνει τη μορφή ή το έτος. Επομένως μπορεί να αποθηκευτεί λάθος τιμή.

3. Το ClientSignature μπορεί να σταλεί ως null όταν δεν υπάρχει υπογραφή,
   αντί για κενό string.

4. Τα reference IDs πρέπει να υπάρχουν στη βάση του συγκεκριμένου tenant.
   Αυτό αφορά τα CustomerID, ContractID, UserID, TicketID, EquipmentID,
   MaintenanceID και InventoryID. Διαφορετικά μπορεί να προκύψει database
   foreign-key error.

5. Μέσα στις αντίστοιχες λίστες είναι υποχρεωτικά τα EquipmentID,
   InventoryID και ToolsID.

ΠΡΟΤΕΙΝΟΜΕΝΗ ΛΥΣΗ
------------------

Άμεση διόρθωση στο frontend:

1. Να δημιουργείται ξεχωριστό create payload και να μη στέλνεται αυτούσιο
   ένα object που χρησιμοποιείται για εμφάνιση στη φόρμα.
2. Να αφαιρεθούν τα ContractName και TicketNumber πριν από το POST.
3. Να διορθωθεί ο τρόπος δημιουργίας του StartDate ώστε να παράγει πάντα
   ISO ημερομηνία YYYY-MM-DD με τετραψήφιο έτος.
4. Να στέλνεται ClientSignature: null όταν δεν υπάρχει υπογραφή.

Προτεινόμενη θωράκιση του backend:

1. Να προστεθεί validation για StartDate και EndDate με αυστηρή μορφή
   YYYY-MM-DD και έλεγχος ότι StartDate <= EndDate.
2. Σε λάθος payload να επιστρέφεται σαφές 400 response με το συγκεκριμένο
   πεδίο που απέτυχε.
3. Να δηλωθεί ρητά η πολιτική για άγνωστα JSON fields. Η ασφαλέστερη επιλογή
   για το συγκεκριμένο API είναι να απορρίπτονται, ώστε λάθη ονοματοδοσίας
   στο frontend να εντοπίζονται άμεσα.
4. Προαιρετικά να ελέγχονται τα reference IDs πριν το insert και να
   επιστρέφεται κατανοητό 400/404 αντί για γενικό database exception.

Η βασική και πιο άμεση λύση είναι να διορθωθεί το frontend payload όπως στο
παραπάνω παράδειγμα. Παράλληλα, το backend validation είναι σημαντικό επειδή
σήμερα η τιμή "0026-01-21" μπορεί να αποθηκευτεί χωρίς να απορριφθεί.
